SWE-HorizonBench — localize, gate, and curate under a 150-line horizon

A zero-runtime-dependency Python toolkit for coding-agent research. Rank ≤150-line read windows with AST-HorizonGraph, enforce two-sided soundness, select serve-cost-aware trajectories with MS-SFT, and probe construct validity on SWE-HorizonBench-OOD (60 tasks · 8 libraries · 0% competition overlap).

AST-HorizonGraph

Parse a Python repo into import / call / sibling / attribute edges, weight issue tokens with sub-token IDF, and return K disjoint ≤150-line windows — the exact read budget many agent harnesses enforce.

Two-sided soundness

A task is usable only if empty-patch tests fail and the human oracle patch makes them pass. Also classifies patch topology S1 / S2 / S3 and the >150-line companion-hunk flag.

MS-SFT selector

Score every sound passing rollout by tokens, steps, excess hunks, and scratch contamination. Keep one serve-cost-optimal winner per task so LoRA fine-tuning stays inside a fixed wall-clock budget.

OOD + @kbench.task

Ship a 60-task out-of-distribution probe across 8 external libraries, plus a 3-task native Kaggle Benchmarks suite that runs offline via a deterministic shim or live with kaggle_benchmarks.

Why a 150-line horizon?

Many coding-agent stacks truncate read_file at 150 lines (or 10k chars). Agents often open the right file yet miss companion edit sites deeper in the same module — Pass@1 collapses from single-hunk to multi-hunk / multi-file topologies. HorizonGraph allocates multiple windows under that hard budget.

Construct-validity warning

Synthetic OOD prompts that name Python symbols inflate lexical and graph recall the same way seeded gold-file pools do. Use OOD as a fast CPU sanity check — not as proof of end-to-end unseeded retrieval.

04

How to use it

CLI + Python API · pick a recipe

Rank K coupling-scored read windows for an issue on any Python repository.

cli · localize 
python3 -m swe_horizon_bench.cli localize \
  --repo /path/to/repo \
  --query "timeout ignored when follow_redirects=False" \
  --seed src/client.py \
  -k 3
python · localize_windows 
from swe_horizon_bench import localize_windows

wins = localize_windows(
    "~/code/myrepo",
    "pluggy hook wrapper order",
    seed_file="src/pluggy/_hooks.py",
    k=3,
)
for w in wins:
    print(w["path"], w["start_line"], w["end_line"], w["score"])
python · soundness + topology 
from swe_horizon_bench import two_sided_sound, classify_topology

gate = two_sided_sound(
    empty_pass=False,   # tests must fail without a patch
    oracle_pass=True,   # human fix must make tests pass
    candidate_pass=True,
)
assert gate["usable"]

topo = classify_topology(open("gold.patch").read())
# topology: S1_single_hunk | S2_single_file_multi_hunk | S3_multi_file
# any_file_delta_L_gt_150: True when companions sit past the 150-line horizon
print(topo["topology"], topo["any_file_delta_L_gt_150"])
python · MS-SFT winner per task 
from swe_horizon_bench import j_ms, select_ms_sft

# J_MS = I[sound] * exp(-α tok/Tmax - β steps/Nmax - γ hunks/gold - δ scratch)
score = j_ms(
    sound=True, tokens=3918, steps=24, hunks=2, gold_hunks=3, scratch=False,
    alpha=1.5, beta=1.0, gamma=0.5, delta=2.0,
)

winners = select_ms_sft([
    {"task_id": "t1", "sound": True, "tokens": 3918, "steps": 24,
     "hunks": 2, "gold_hunks": 3, "scratch": False},
    {"task_id": "t1", "sound": True, "tokens": 6200, "steps": 40,
     "hunks": 5, "gold_hunks": 3, "scratch": True},
])
print(winners["t1"]["j_ms"], score)
